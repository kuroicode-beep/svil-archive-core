## 4. Findings

### Critical: capability token accepts missing target when a token is scoped to a target

File: `app/flutter_app/lib/data/relay/relay_capability_token_service.dart`

`validate()` only rejects target mismatches when the incoming `targetDocumentId` or `targetPath` is non-null. If the stored token has `target_document_id` or `target_path`, but the relay result omits both target fields, validation can still return `true` as long as the token hash, task id, expiry, and action match.

Relevant code:

- Stored target fields: lines 49-51
- Validation target checks: lines 88-106

Why this matters:

- The Sprint 01 instruction explicitly requires `allowed_target` to match `target_document_id` or `target_path`.
- A relay result with a valid token but no target can bypass the target binding.
- Existing Sprint 01 tests cover invalid token rejection, but not valid-token-with-missing-target rejection.

Required rework:

- Reject when a stored target is present and the corresponding result target is missing.
- Normalize and compare target paths if path targets are supported.
- Add regression tests for:
  - valid token + missing target document id => rejected
  - valid token + wrong target document id => rejected
  - valid token + matching target document id => accepted
  - valid token + missing/wrong target path => rejected
