# SVIL Archive Core 개인 데이터 아카이브 모듈 v0.1 — 루미

작성일: 2026-06-05  
작성자: 루미

## 한 줄 정의

개인 데이터 아카이브는 사용자가 남긴 Markdown 문서에서 관심사, 핵심 주제, 중단된 아이디어, 현재 프로젝트 상태를 발췌해 AI가 답변에 활용할 수 있는 개인 컨텍스트로 가공하는 기능이다.

---

## 목적

SVIL Archive Core는 단순히 문서를 저장하는 앱이 아니라, 문서 속에 흩어진 사용자의 생각 흐름을 다시 찾아주는 시스템이 될 수 있다.

개인 데이터 아카이브의 목적은 다음과 같다.

- 최근 관심사 파악
- 핵심 주제 발췌
- 반복 질문 추적
- 중단된 아이디어 발견
- 현재 프로젝트 상태 분석
- 타임라인 기반 변화 추적
- AI 답변에 활용 가능한 컨텍스트 패킷 생성

이 기능은 사용자를 감시하거나 평가하는 것이 아니라, 사용자가 직접 남긴 기록을 바탕으로 잊힌 흐름을 다시 꺼내는 기억 보조 시스템이다.

---

## 핵심 기능

### 1. 최근 문서 저장 트렌드 분석

최근 생성되거나 수정된 문서를 분석해 사용자의 관심 흐름을 파악한다.

분석 항목:

- 최근 자주 생성한 문서 유형
- 최근 많이 등장한 프로젝트
- 반복적으로 등장하는 키워드
- 새롭게 증가한 관심사
- 줄어든 관심사
- 중단된 주제
- 문서 작성 빈도 변화
- 특정 기간에 집중된 작업 분야

예시:

```text
최근 30일 분석:
- Notion 대체 구조 관련 문서 증가
- Markdown / GitHub / MCP 관련 키워드 급증
- OpenClaw 운영 자동화 주제 지속
- 블로그 / 유튜브 DB 구축은 보류 상태
```

---

### 2. 개인 핵심 주제 자동 발췌

문서 내용에서 사용자의 핵심 주제, 사상, 관심사, 질문, 작업 스타일을 발췌한다.

추출 항목:

- 핵심 관심사
- 현재 고민
- 반복 질문
- 장기 프로젝트
- 중단된 아이디어
- 자주 쓰는 표현
- 중요하게 여기는 가치
- 선호하는 도구
- 피하고 싶은 방식
- 의사결정 기준

예시:

```yaml
person_profile:
  current_interests:
    - AI 친화적 문서 아카이브
    - MCP 기반 통신 프로토콜
    - Markdown 원본 저장소
    - 로컬 AI 자동화
  core_values:
    - 도구보다 프로토콜
    - 자동화보다 구조
    - 유행보다 지속성
    - AI보다 협업 방식
  avoided_patterns:
    - 플랫폼 락인
    - 블록 제한
    - 과도한 유료 구독
    - 설명만 하고 실행하지 않는 워크플로우
```

---

### 3. 현재 상태 분석

문서 기반으로 사용자의 현재 작업 상태와 관심사의 위치를 분석한다.

분석 항목:

- 현재 가장 활발한 프로젝트
- 최근 멈춘 프로젝트
- 재개 가능성이 있는 아이디어
- 문서화는 되었지만 실행되지 않은 주제
- 실행 중이지만 보고서가 없는 작업
- 반복 언급되지만 아직 구조화되지 않은 문제
- 최근 의사결정의 방향성

예시:

```text
현재 상태 요약:

소장님은 Notion 중심 운영에서 Markdown + GitHub + Cloud Drive 기반 구조로 이동하려는 전환점에 있다.
SVIL Archive Core는 단순 아이디어가 아니라 Notion 한계에서 파생된 실질적 대체 시스템 후보로 부상했다.
```

---

### 4. 중단된 아이디어 / 보류 프로젝트 추적

과거에는 자주 등장했지만 최근 언급이 줄어든 아이디어를 추적한다.

목적은 압박이 아니라 재발견이다.

추적 항목:

- 중단된 프로젝트
- 보류된 아이디어
- 후속 문서가 없는 기획
- 완료보고서가 없는 작업
- 검증보고서가 없는 개발 건
- 루미의 일기에 등장했지만 이후 문서화되지 않은 주제

예시:

```text
보류 후보:
- 블로그 DB 구축
- 유튜브 DB 구축
- SVIL Project Lifecycle 문서화
- Notion Agent Protocol 문서화
- SVIL H2 2026 선언문
```

---

### 5. 타임라인 기반 분석

문서를 시간순으로 정리해 생각과 프로젝트의 변화를 보여준다.

타임라인 단위:

- 일간
- 주간
- 월간
- 프로젝트별
- 주제별
- AI별
- 문서 타입별

예시:

```text
2026-06-04
- SVIL 하반기 운영 방향 정리
- Notion을 AI 통신 프로토콜로 정의
- OpenClaw를 운영실 직원으로 재정의

2026-06-05
- Notion 블록 제한 문제 발생
- Markdown + GitHub + Cloud Drive 구조 검토
- SVIL Archive Core 아이디어 등장
- 개인 데이터 아카이브 기능 제안
```

## AI 답변용 컨텍스트 패킷

추출된 개인 데이터는 AI가 답변에 활용 가능한 형태로 가공한다.

목표는 AI가 매번 처음 만난 사람처럼 답하지 않게 만드는 것이다.

가공 항목:

- 요약 프로필
- 최근 관심사
- 현재 진행 중인 프로젝트
- 중단된 아이디어
- 선호하는 답변 방식
- 피해야 할 표현 방식
- 프로젝트별 현재 상태
- 최근 결정사항
- 참고 문서 링크

예시:

```yaml
ai_context_packet:
  user_name: "인블루"
  preferred_call: "오빠"
  current_focus:
    - SVIL Archive Core
    - Notion 대체 구조
    - AI 친화적 Markdown 아카이브
  active_projects:
    - SVIL 운영 구조
    - OpenClaw 운영실
    - Archive Core
  paused_projects:
    - 블로그 DB
    - 유튜브 DB
    - Project Lifecycle 문서화
  response_preferences:
    - 설명보다 실행 우선
    - 문서화 가치가 있으면 Markdown 원본 생성
    - 선지자처럼 말하지 않기
    - 구조 중심으로 정리
```

## 추출 작업 처리 방식

개인 데이터 추출은 비용과 프라이버시를 고려해 로컬 중심으로 처리한다.

기본 처리:

- 로컬 LLM / Ollama 사용
- 문서 메타데이터 우선 분석
- 필요한 문서만 본문 분석
- 결과는 로컬에 저장
- 민감 정보는 외부 API로 보내지 않음

선택 처리:

- DeepSeek API 등 외부 API 사용 가능
- 긴 문서 요약 또는 복잡한 관계 분석에만 사용
- 사용 전 명시적 승인
- 외부 API로 보낸 문서 기록 저장

## 프라이버시 원칙

개인 데이터 아카이브는 민감한 기능이다.

따라서 다음 원칙이 필요하다.

- 기본 저장 위치는 로컬
- 외부 API 사용 전 승인
- 원본 문서와 추출 데이터 분리
- 삭제 가능한 구조
- 추출 근거 문서 표시
- 사용자가 추출 결과를 수정 가능
- AI 답변에 사용할 범위 선택 가능
- 민감 정보 자동 마스킹 옵션

## MVP 기능

1. 최근 문서 30일 트렌드 분석
2. 핵심 키워드 자동 추출
3. 관심사 목록 생성
4. 중단된 아이디어 후보 추출
5. 프로젝트 상태 요약
6. 타임라인 자동 생성
7. AI 답변용 context packet 생성
8. 로컬 LLM 기반 처리
9. DeepSeek API 선택 처리
10. 사용자 검토 / 수정 UI

## 루미 판단

이 기능은 SVIL Archive Core의 중요한 차별점이 될 수 있다.

일반 노트앱은 문서를 저장한다.

하지만 SVIL Archive Core는 문서에서 사용자의 흐름을 발췌하고, 그 흐름을 다시 AI 협업에 사용할 수 있게 만든다.

즉, 단순 저장소가 아니라 기억을 재가공하는 시스템이다.

한 줄로 표현하면:

> 개인의 문서에서 현재의 나와 과거의 아이디어를 다시 꺼내 AI가 활용 가능한 기억으로 만드는 기능.
